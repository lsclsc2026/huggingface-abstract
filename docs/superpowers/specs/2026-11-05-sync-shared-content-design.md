# 同步与公共内容分离

用户已确认本轮优先实现原需求 2–7，多用户认证与公网产品化暂缓。

## 目标与约束

- 每 15 分钟检查一次所有新增文章；已有任务不并发重启。16:00 之后继续同步论文。
- 16:00 后生成一次共享导读，成功后固定；失败按检查间隔重试。
- 论文分析和导读不接收个人兴趣、身份或阅读风格，选文也不受个人分数影响。
- 关键词仅影响固定、可复现的个人相关度及排序，不调用生成模型。
- 原私人笔记区替换为“评论区 / 暂未开放”，保留旧数据，不公开旧笔记。
- 不覆盖生产配置、数据库或下载文件；云端部署前备份。所有代码由 Git 管理并上传用户 GitHub。

## 实现选择（开发者决定）

保留 FastAPI、SQLite、原生前端，避免在本轮引入认证和向量基础设施。评分先使用明确的关键词匹配比例，匹配只看标题、摘要及 HF 关键词；不混入社区点赞和模型评分。中文关键词补充固定的常见英文研究术语映射，规则与说明随代码版本保存。将评分单独存入现有 relevance 列，分析 JSON 不再保存个人分数。

备选为嵌入向量余弦相似度：语义覆盖更好，但需要新增模型、下载与缓存策略；用户将向量库作为举例而非强制要求，留作后续替换。模型直接评分不可复现且增加费用，不采用。

共享生成使用固定的简体中文科普编辑风格。导读按社区热度与论文 ID 确定顺序，保留当前 top_n=18 的统一上限，不接收个人分数。不自动重建旧正文和导读，以免重复模型费用和破坏固定导读；新内容使用 shared-v5 提示词标识。旧内容的个人评分字段在 API 读取时去除，正文历史来源保留说明。

## 同步调查与处理

已确认云端 15 篇；官方 API、官方日期页、官方首页均返回 16 篇，镜像 API 返回空而镜像网页有 16 篇。已发现网页兜底只在 API 为空时执行，API 非空但滞后时无法补全。修复为 API 与对应日期页面按 ID 合并，验证页面日期；两条链路均失败时明确报错。保留单一路径成功时的可用结果，避免部分错误中断整个同步。请求日期决定 daily_date，不用论文原始发布日期代替日报归属。镜像详情抓取应使用镜像地址。

19 篇的差异尚缺来源证据，不伪造或补入其他日期文章；继续比对用户提供的页面。同步只新增及更新元数据，不删除已有文章或已有分析。

## 验收

HTTP 受控响应验证部分 API、网页更多文章、单源失败、日期不符、重复 ID；临时数据库验证 15 分钟边界、16:00 前后、失败重试、已有分析不重做、导读不随新增文章变化。对不同个人设置比较实际模型请求及公共正文，验证一致；改兴趣仅更新 relevance。运行完整测试、JS 语法检查、页面交互检查。部署后确认版本、抓取数、摘要状态、运行记录与备份位置。
