# 方法正文依据与有界读取

用户已确认实施上一轮方案；保持全部UI和摘要/术语/贡献版式，仅更新方法生成依据，不批量重做历史。

1. 测试先行：HTML方法分节覆盖、无正文和错误证据拒绝、PDF文字备用、单次调用/缓存、不可信响应的确定性降级。
2. 本地提取：arXiv HTML优先，方法正文按子节分配预算，保留编号片段、章节与来源；找不到正文再读取PDF文本，限制下载、页数、解析进程资源/时间；无OCR或模型预摘要。来源缓存独立升级。
3. 模型仍一次完成分析：方法以自然段和原文引句返回；校验片段ID与原文引句存在，只接受有有效证据的段落。没有正文时固定说明未取得；证据不合法时不展示其方法内容、不请求模型修复。内部证据随分析保存但不改变页面。
4. 验证：完整pytest、JS语法、真实arXiv来源检查；临时数据库中小样本真实模型调用观察usage与效果，禁止批量历史改写；独立审查。
5. 交付：备份云端源码/配置/SQLite，等待在途任务结束再部署；保持15分钟自动调度，核对代码/私有数据保留；更新HANDOFF和GitHub。

边界：引句匹配证明引用原文存在，不保证中译的语义完全正确；扫描PDF或章节识别失败宁可留缺。字符/词数预算用于限制输入，不冒充网关精确token数，实际用量看usage。正文缺失/错误时不额外调用修复模型。
