# 模型选型建议

> 更新时间：2026-11-05  
> 关联：[prompt-v4.md](prompt-v4.md) · [HANDOFF.md](../HANDOFF.md)  
> 配置文件：项目根目录 `config.yaml` 的 `llm:` 段

## 1. 先说结论

Paper Daily 的输出质量不是单靠提示词决定的。按影响从大到小：

1. **输入上下文**：只有摘要时，模型无法可靠解释实验细节；
2. **模型能力**：中文表达、概念抽象、长文结构化输出；
3. **提示词**：决定模型“怎么讲”；
4. **评估与反馈**：决定能否持续变好。

对于 v4 的深度科普输出，建议：

| 场景 | 建议 |
| --- | --- |
| 日常使用 | 有强中文能力的 **reasoning 模型**，上下文 ≥ 32K，输出 ≥ 8K |
| 更高质量 | 单篇与日报都使用同一档强模型；或日报使用更强的“主编模型” |
| 本地/私有化 | Qwen3 32B 起步；7B/14B 容易出现空泛、类比生硬、术语解释不完整 |
| 低成本实验 | 先用 `fetch.max_papers: 3` 验证，不要一上来 35 篇全量跑 |

关键不是“参数越大越好”，而是：

- 中文写作自然，不是翻译腔；
- 能稳定输出严格 JSON；
- 能做多步推理，能区分“作者声称”和“证据”；
- 能理解“给非专业读者解释”这一指令，而不是复述摘要。

## 2. 推荐模型类型

以下是“能力档位”，不是必须购买的品牌清单；以你能访问的模型为准。

### 第一档：最适合本项目的日报

- 强推理 + 强中文的旗舰/次旗舰模型；
- 上下文 ≥ 64K 更从容；
- 支持 `reasoning_effort` / thinking 模式；
- 例：DeepSeek 推理系列、Qwen 大参数版本、Claude/GPT/Gemini 的最新强模型。

适合：

- 生成 1800–2600 字的跨论文导读；
- 组织概念依赖关系；
- 主动澄清容易误解的概念，并说明适用边界。

### 第二档：性价比日常档

- 32B 级别以上的开源/私有模型；
- 中文和 JSON 稳定性经过验证；
- 上下文 ≥ 32K。

适合：

- 单篇论文解读；
- 日报使用第一档模型。

### 不推荐作为默认

- 7B/14B 小模型：容易把“解释”写成“换一种说法”，类比与误解澄清经常缺失；
- 纯翻译/摘要微调模型：不擅长概念教学；
- 只优化的“flash/mini”速度档：可以用于测试，但不适合直接生成最终日报。

## 3. 当前配置的调参建议

```yaml
llm:
  max_tokens: 8000
  timeout_seconds: 300
  concurrency: 2
  reasoning_effort: "high"   # 仅模型支持时
  temperature: 0.25
```

说明：

- **`max_tokens`**：v4 输出更长，6000 是下限，8000 更稳；如果 provider 上限低，优先保证 `misconceptions`、`jargon` 和 `limitations` 不被截断。
- **`timeout_seconds`**：推理模型 + 长输出，240 秒可能偏紧，建议 300。
- **`concurrency`**：如果 provider 限流，降到 2；本地 32B 模型建议 1。
- **`reasoning_effort`**：模型支持时才填；不支持会触发自动降级。

## 4. 比换模型更重要的三件事

### 4.1 输入不能只有摘要

当前 v4 仍然只使用标题、摘要、HF 摘要和关键词。对于“实验怎么做、失败模式是什么、和基线差多少”，摘要经常不够。

下一步最值得做的架构升级：

- 可选下载 PDF；
- 提取正文/方法/实验部分；
- 截断后放入上下文；
- 明确标注“以下来自全文，以下来自摘要”。

这比单纯换更贵的模型更能提高“深度理解”。

### 4.2 日报需要跨论文的二次组织

v4 已经让日报拿到每篇的 `problem / jargon / contrast / misconceptions / findings`，而不是只有 `tldr`。这是关键改进。

更进一步可以做 **两阶段日报**：

1. 概念抽取：从当天论文中抽取概念、定义、关系、证据；
2. 主编写作：基于结构化概念图写导读。

代价是更多 token 和一次额外调用，但能显著减少“日报只是摘要拼接”。

### 4.3 建立小规模人工评估集

不要只用“看起来不错”判断提示词。建议固定 5 篇论文 + 1 天日报，按以下维度打分：

- 概念是否真的解释清楚；
- 是否说明了旧做法与差异；
- 是否区分论文声明与证据；
- 是否主动澄清容易误解之处，并说明适用边界；
- 是否有事实错误；
- 中文是否自然。

每次改提示词或换模型，用同一组样本对比。没有这个，提示词很容易“越改越长，但没有更好”。

## 5. 推荐组合

### 预算充足

- 单篇：强 reasoning 模型；
- 日报：同档或更强模型；
- `max_tokens: 8000`；
- 后续加 PDF 全文。

### 预算有限

- 单篇：32B 级中文模型，`max_tokens: 5000`；
- 日报：DeepSeek 推理系列或同类强模型；
- `fetch.max_papers: 10–15` 做日报；
- 不追求一次覆盖全部 35 篇。

### 完全本地

- Qwen3 32B 或同级模型；
- vLLM / SGLang 部署；
- `concurrency: 1`，`timeout_seconds: 600`；
- 先跑 3 篇验证 JSON 和中文质量，再全量。

## 6. 当前代码的限制

- 单篇和日报共用同一个 `llm` 配置，暂不支持“日报使用另一个模型”。
- 没有自动模型路由。
- 没有基于读者反馈的术语记忆。
- 没有全文解析。
- 没有质量评估集。

这些是下一步可做的方向，不应通过无限加长提示词来掩盖。

## 7. 一次全量提取的成本估算（2026-11-05）

以“当天 35 篇论文 + 1 份日报”为一次完整运行，按真实摘要长度和 v4 提示词估算：

- 每篇输入约 2,100–2,500 tokens（含系统提示词）；
- 35 篇输入约 75k–90k tokens；
- 日报上下文约 12k–18k tokens；
- 每篇输出约 700–1,100 tokens；
- 日报输出约 1,000–1,500 tokens；
- 总输入约 90k–110k tokens，总输出约 25k–40k tokens。

图片中的 Qwen 价格折算：

| 模型 | 输入 / 输出（每 1M） | 一次全量估算 |
| --- | --- | --- |
| qwen3.8-max | $3.6 / $10.8 | **约 $0.65–0.95** |
| qwen3.7-max | $3.6 / $10.8 | 约 $0.65–0.95 |
| qwen3.7-plus | $0.6 / $2.4 | 约 $0.15–0.22 |
| qwen3.8-flash | $0.24 / $0.81 | 约 $0.05–0.08 |

注意：

- 以上假设单次运行、没有失败重试、没有重复刷新；重跑一次就是再花一遍。
- 如果模型把隐藏 reasoning token 计入输出，成本可能再高 20–80%。
- 系统提示词在 35 篇中相同，若 provider 的缓存命中，输入成本会下降；未命中则按上表上限附近计算。
- `max_tokens: 8000` 是上限，不等于会计费 8000；按实际生成 token 计费。
- 若把 `fetch.max_papers` 降到 20，按约 60% 估算；日报的 `digest.top_n` 也会影响成本。

**结论**：qwen3.8-max 做一次全量通常能压到 $1 以内，但安全边际不大；qwen3.7-plus 更适合作为日常默认，qwen3.8-flash 不建议作为最终日报主笔。
